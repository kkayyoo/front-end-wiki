# 事件循环（Event Loop）

## 为什么需要事件循环？

JS 是**单线程**语言（浏览器主线程负责渲染 + JS 执行），无法同时处理多个任务。事件循环是 JS 处理异步操作的核心机制。

## 执行模型

```
调用栈（Call Stack）
     ↓ 同步代码执行完毕
检查微任务队列（Microtask Queue）→ 清空所有微任务
     ↓
检查宏任务队列（Macrotask Queue）→ 取出一个宏任务执行
     ↓
重复（循环）
```

## 宏任务 vs 微任务

| 类型 | 包含 |
|------|------|
| **宏任务** | `script`整体代码、`setTimeout`、`setInterval`、`AJAX`、`DOM事件`、`UI渲染`、`setImmediate`(Node.js) |
| **微任务** | `Promise.then/catch/finally`、`MutationObserver`、`queueMicrotask`、`process.nextTick`(Node.js，优先级最高) |

> **关键规则**：每个宏任务执行后，会**清空所有微任务**，再执行下一个宏任务。

## 经典执行顺序题（大厂必考）

```js
console.log('1');
setTimeout(() => {
  console.log('2');
  Promise.resolve().then(() => {
    console.log('3');
  });
}, 0);
Promise.resolve().then(() => {
  console.log('4');
  setTimeout(() => {
    console.log('5');
  }, 0);
});
console.log('6');
```

**答案：1 → 6 → 4 → 2 → 3 → 5**

逐步解析：
1. `console.log('1')` — 同步，输出 **1**
2. `setTimeout(cb1)` — 宏任务队列：[cb1]
3. `Promise.then(cb2)` — 微任务队列：[cb2]
4. `console.log('6')` — 同步，输出 **6**
5. 调用栈清空 → 执行微任务 cb2：输出 **4**，并推入宏任务：[cb1, cb3]
6. 微任务清空 → 执行宏任务 cb1：输出 **2**，推入微任务 [cb4]
7. 执行微任务 cb4：输出 **3**
8. 执行宏任务 cb3：输出 **5**

## 进阶题：async/await 的本质

```js
async function async1() {
  console.log('async1 start');    // 2
  await async2();
  console.log('async1 end');      // 6（await 后面的代码 = Promise.then）
}
async function async2() {
  console.log('async2');          // 3
}
console.log('script start');      // 1
setTimeout(() => {
  console.log('setTimeout');      // 8
}, 0);
async1();
new Promise((resolve) => {
  console.log('promise1');        // 4
  resolve();
}).then(() => {
  console.log('promise2');        // 7
});
console.log('script end');        // 5
```

**答案：script start → async1 start → async2 → promise1 → script end → async1 end → promise2 → setTimeout**

> **关键**：`await async2()` 相当于 `Promise.resolve(async2()).then(() => { /* async1 end */ })`，其后续代码进微任务队列。

## 实际开发踩坑

### 1. setTimeout(fn, 0) 不是真正的 0ms

```js
// 浏览器规范：最小 4ms（嵌套超过 5 层时）
// 实际可能 1-16ms，取决于系统和浏览器负载
setTimeout(() => console.log('延迟执行'), 0);
console.log('同步执行'); // 先输出
```

### 2. Promise 链中的错误处理

```js
// ❌ 未捕获的 Promise rejection 会触发 unhandledRejection
fetch('/api/data')
  .then(res => res.json())
  // 忘记 .catch()

// ✅ 始终加 catch
fetch('/api/data')
  .then(res => res.json())
  .catch(err => console.error(err));

// 或用 async/await + try/catch
async function fetchData() {
  try {
    const res = await fetch('/api/data');
    return await res.json();
  } catch (err) {
    console.error(err);
  }
}
```

### 3. 微任务导致 UI 阻塞

```js
// ❌ 递归微任务：页面会卡死，UI 永远不更新！
function loop() {
  Promise.resolve().then(loop); // 微任务队列永远不清空
}
loop();

// ✅ 改用 setTimeout 让 UI 有机会渲染
function loop() {
  setTimeout(loop, 0);
}
```

## 面试高频题

**Q: Promise.then 和 setTimeout 谁先执行？**
> `Promise.then`（微任务）先于 `setTimeout`（宏任务）执行。同一轮事件循环中，微任务队列清空后才执行下一个宏任务。

**Q: Node.js 和浏览器的 Event Loop 有什么区别？**
> Node.js 有额外的阶段（timers、I/O、idle、poll、check、close），`process.nextTick` 优先级高于 `Promise.then`，`setImmediate` 在 check 阶段执行。浏览器的 Event Loop 更简单，没有这些阶段划分。

**Q: queueMicrotask 是什么？**
```js
// 显式将函数加入微任务队列，等价于 Promise.resolve().then(fn)
queueMicrotask(() => console.log('微任务'));
// 用途：避免创建 Promise 对象的开销，性能更好
```
