# 作用域与变量提升

## 作用域类型

JS 采用**词法作用域（静态作用域）**，作用域在代码书写时就确定，而非执行时。

| 类型 | 说明 | 创建方式 |
|------|------|---------|
| 全局作用域 | 整个脚本可访问 | 顶层声明 |
| 函数作用域 | 函数内部可访问 | `function` 声明 |
| 块级作用域 | `{}` 内可访问 | `let/const` + `{}`（if/for/switch） |

## var vs let vs const

```js
// var：函数作用域，有变量提升，可重复声明
var x = 1;
var x = 2; // 不报错
console.log(x); // 2

// let：块级作用域，无变量提升（TDZ），不可重复声明
let y = 1;
// let y = 2; // SyntaxError

// const：块级作用域，声明时必须赋值，绑定不可变（但对象内容可变）
const OBJ = { a: 1 };
OBJ.a = 2;    // ✅ 可以修改属性
// OBJ = {};  // ❌ 不能重新赋值
```

## 变量提升（Hoisting）

```js
// var 提升：声明提升，但赋值不提升
console.log(a); // undefined（不报错）
var a = 10;
// 等价于：
var a;          // 提升到顶部
console.log(a); // undefined
a = 10;

// 函数声明整体提升
sayHi(); // 'Hi!' ← 可以在声明前调用
function sayHi() { console.log('Hi!'); }

// 函数表达式不提升
sayHello(); // TypeError: sayHello is not a function
var sayHello = function() { console.log('Hello!'); }
```

## 暂时性死区（TDZ）

```js
// let/const 声明前的区域称为 TDZ，访问会报错
console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 10;

// 实际踩坑：typeof 也无法绕过 TDZ
typeof b; // ReferenceError（let b 存在时）
typeof undeclaredVar; // 'undefined'（未声明的变量，typeof 返回 undefined）
```

> **实际开发**：TDZ 是 `let/const` 的有意设计，防止"使用未初始化变量"的 bug。写代码时始终先声明后使用。

## 作用域链

```js
let globalVar = 'global';

function outer() {
  let outerVar = 'outer';

  function inner() {
    let innerVar = 'inner';
    console.log(innerVar);  // 'inner'（当前作用域）
    console.log(outerVar);  // 'outer'（上层作用域）
    console.log(globalVar); // 'global'（全局作用域）
  }
  inner();
}
```

作用域链：`inner` → `outer` → `global` → `null`

## 经典面试题

### 循环 + var 陷阱

```js
// ❌ 输出 5 个 5
for (var i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 0);
}
// 原因：var 是函数/全局作用域，循环结束后 i=5，所有回调共享同一个 i

// ✅ 方案1：let（块级作用域，每次迭代独立绑定）
for (let i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 0); // 0 1 2 3 4
}

// ✅ 方案2：IIFE 闭包
for (var i = 0; i < 5; i++) {
  ((j) => setTimeout(() => console.log(j), 0))(i);
}

// ✅ 方案3：bind
for (var i = 0; i < 5; i++) {
  setTimeout(console.log.bind(null, i), 0);
}
```

### 函数提升 vs 变量提升优先级

```js
// 函数声明优先级高于 var
console.log(typeof foo); // 'function'（不是 'undefined'）
var foo = 'bar';
function foo() {}
```

## 面试高频题

**Q: let 和 const 有变量提升吗？**
> 有，但存在 TDZ（暂时性死区）。声明被提升到块的顶部，但初始化不提升，访问会抛出 `ReferenceError`。

**Q: 为什么推荐用 const 而不是 let？**
> `const` 声明传达"该绑定不会改变"的语义，减少心智负担，代码更可预测。ESLint 的 `prefer-const` 规则也鼓励这一做法。需要重新赋值时才用 `let`。

**Q: 什么是执行上下文（Execution Context）？**
> 代码执行时创建的环境，包含：变量环境（Variables）、词法环境（Lexical）、`this` 绑定。每次函数调用创建新的执行上下文，压入调用栈（Call Stack）。
