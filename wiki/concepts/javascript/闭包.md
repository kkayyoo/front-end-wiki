# 闭包（Closure）

## 定义

**内部函数访问外部函数的变量/参数，且该内部函数被外部引用，就形成闭包。**

本质：函数 + 其词法环境的绑定关系。

```js
function outer() {
  let count = 0; // 外部变量
  return function inner() {
    count++; // 内部函数访问外部变量
    return count;
  };
}
const counter = outer();
counter(); // 1
counter(); // 2  ← count 被"记住"了，这就是闭包
```

## 应用场景

### 1. 封装私有属性

```js
function Person(name) {
  let _age = 0; // 私有变量，外部无法直接访问

  return {
    getName: () => name,
    getAge: () => _age,
    setAge: (val) => { if (val >= 0) _age = val; }
  };
}

const p = Person('张三');
p.getName(); // '张三'
p.setAge(25);
p.getAge();  // 25
p._age;      // undefined ✅ 外部访问不到
```

> **实际开发**：ES2022 已有 `#privateField` 语法，但闭包实现私有属性的思路在面试中仍是必考。

### 2. 函数工厂 / 柯里化

```js
function multiply(factor) {
  return (num) => num * factor; // 记住了 factor
}
const double = multiply(2);
const triple = multiply(3);
double(5); // 10
triple(5); // 15
```

### 3. 防抖 / 节流

```js
function debounce(fn, delay) {
  let timer = null; // 闭包保存 timer
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

### 4. 模块化（ES Module 之前）

```js
const store = (() => {
  let state = {}; // 私有 state
  return {
    get: (key) => state[key],
    set: (key, val) => { state[key] = val; }
  };
})();
```

## 经典陷阱：循环中的闭包

```js
// ❌ 经典错误：5 个 setTimeout 都输出 5
for (var i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 100);
}

// ✅ 方案1：用 let（块级作用域，每次迭代新绑定）
for (let i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 100); // 0 1 2 3 4
}

// ✅ 方案2：IIFE 包裹（用闭包固定 i）
for (var i = 0; i < 5; i++) {
  ((j) => setTimeout(() => console.log(j), 100))(i);
}
```

> **实际面试**：这题在字节、腾讯、阿里出现频率极高。答出三种方案（let / IIFE / bind）加分明显。

## 内存泄漏

```js
// ❌ 常见内存泄漏：DOM 引用 + 闭包
function bindEvent() {
  const el = document.getElementById('btn'); // 强引用 DOM
  el.addEventListener('click', function() {
    console.log(el.textContent); // 闭包引用 el
  });
  // 即使移除 DOM，el 也不会被 GC，因为 handler 还持有引用
}

// ✅ 修复：移除监听器时解除引用
function bindEvent() {
  const el = document.getElementById('btn');
  function handler() {
    console.log(el.textContent);
  }
  el.addEventListener('click', handler);
  return () => {
    el.removeEventListener('click', handler);
    // el = null; // 可选：主动释放
  };
}
```

> **实际踩坑**：React 的 `useEffect` 如果没有 cleanup，闭包持有旧状态会造成"stale closure"问题，是 hooks 中最常见的 bug 之一。

## 闭包 vs 普通函数

| 特点 | 普通函数 | 闭包 |
|------|---------|------|
| 执行后变量 | 被 GC 回收 | 仍保留在内存 |
| 状态 | 无状态 | 有状态（记住上下文） |
| 内存占用 | 低 | 较高 |
| 使用场景 | 无状态计算 | 需要持久化状态的场景 |

## 面试高频题

**Q: 闭包会导致内存泄漏吗？怎么解决？**
> 不是闭包本身导致泄漏，而是滥用或忘记释放。解决方案：
> 1. 不需要时将引用设为 `null`
> 2. 用 `WeakMap/WeakSet` 存储对象引用（弱引用，不阻止 GC）
> 3. 移除事件监听器时同步解除闭包引用

**Q: 什么是"stale closure"（过期闭包）？**
```js
// React Hooks 经典 bug
function Counter() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => {
      console.log(count); // 永远打印 0！闭包捕获了初始值
    }, 1000);
    return () => clearInterval(id);
  }, []); // ← 空依赖数组，不更新闭包
}
// 修复：加入 count 依赖，或用 useRef 保存最新值
```
