# 深浅拷贝

## 为什么需要拷贝？

```js
// 引用类型赋值 = 地址共享，修改会互相影响
const a = { x: 1, nested: { y: 2 } };
const b = a;
b.x = 99;
console.log(a.x); // 99 ← a 也变了！
```

## 浅拷贝

只拷贝第一层，嵌套对象仍共享引用。

```js
// 方法1：Object.assign
const b = Object.assign({}, a);

// 方法2：展开运算符（最常用）
const b = { ...a };
const arr = [...originalArr];

// 验证：浅拷贝的局限
const a = { x: 1, nested: { y: 2 } };
const b = { ...a };
b.x = 99;          // a.x 不变 ✅
b.nested.y = 99;   // a.nested.y 也变了！❌ 嵌套对象仍共享
```

> **实际踩坑**：Redux reducer 里常用展开运算符更新 state，但只是浅拷贝，嵌套对象需要逐层展开。

## 深拷贝

完全独立的副本，嵌套对象也不共享。

### 方法对比

| 方法 | 优点 | 缺点 |
|------|------|------|
| `JSON.parse(JSON.stringify())` | 简单 | 丢失 `undefined/Function/Symbol/Date/RegExp`，不处理循环引用 |
| `structuredClone()` | 原生，支持循环引用 | 不支持 `Function/Symbol/DOM节点` |
| 手写递归 | 完全可控 | 需要处理各种边界 |
| lodash `_.cloneDeep` | 生产可用，处理完整 | 引入依赖 |

```js
// JSON 方法（快速但有坑）
const b = JSON.parse(JSON.stringify(a));
// 坑：
JSON.parse(JSON.stringify({ fn: () => {}, date: new Date(), undef: undefined }))
// → {} 函数消失，Date 变字符串，undefined 消失

// structuredClone（现代浏览器推荐）
const b = structuredClone(a); // 支持循环引用、Date、Map、Set、ArrayBuffer
structuredClone({ fn: () => {} }); // ❌ 不支持函数

// lodash（生产项目推荐）
import _ from 'lodash';
const b = _.cloneDeep(a);
```

### 手写深拷贝

```js
function deepClone(obj, map = new WeakMap()) {
  // 处理原始类型和 null
  if (obj === null || typeof obj !== 'object') return obj;

  // 处理循环引用
  if (map.has(obj)) return map.get(obj);

  // 处理特殊类型
  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj);
  if (obj instanceof Map) {
    const cloned = new Map();
    map.set(obj, cloned);
    obj.forEach((val, key) => cloned.set(deepClone(key, map), deepClone(val, map)));
    return cloned;
  }
  if (obj instanceof Set) {
    const cloned = new Set();
    map.set(obj, cloned);
    obj.forEach(val => cloned.add(deepClone(val, map)));
    return cloned;
  }

  // 处理数组和普通对象
  const cloned = Array.isArray(obj) ? [] : {};
  map.set(obj, cloned); // 先存入 map，防止循环引用

  for (const key of [...Object.keys(obj), ...Object.getOwnPropertySymbols(obj)]) {
    cloned[key] = deepClone(obj[key], map);
  }
  return cloned;
}

// 测试循环引用
const a = { x: 1 };
a.self = a; // 循环引用
const b = deepClone(a);
b.x = 99;
console.log(a.x); // 1 ✅
```

> **面试技巧**：手写深拷贝时，先说出用 `WeakMap` 处理循环引用是关键，面试官会直接问这个。用 `WeakMap` 而非 `Map` 是因为弱引用不阻止 GC。

## 实际开发场景

```js
// 场景1：表单编辑，需要独立副本防止影响原始数据
const formData = structuredClone(originalData);

// 场景2：React 状态更新（不可变数据）
// 浅拷贝适用于顶层属性变更
setState(prev => ({ ...prev, name: '新名字' }));

// 嵌套对象需要逐层展开（或用 immer）
setState(prev => ({
  ...prev,
  user: { ...prev.user, address: { ...prev.user.address, city: '上海' } }
}));
// 用 immer 更优雅：
import produce from 'immer';
setState(produce(draft => { draft.user.address.city = '上海'; }));

// 场景3：深比较前做快照
const snapshot = structuredClone(state);
// ... 一系列操作
if (JSON.stringify(state) !== JSON.stringify(snapshot)) {
  // 状态变了
}
```

## 面试高频题

**Q: 实现深拷贝时如何处理循环引用？**
> 用 `WeakMap` 记录已拷贝的对象，每次拷贝前先检查 Map 中是否已存在，存在则直接返回缓存，避免无限递归。

**Q: 什么时候用浅拷贝，什么时候用深拷贝？**
> - 浅拷贝：数据是扁平结构，或只需更新顶层属性（性能更好）
> - 深拷贝：嵌套对象需要完全独立，修改副本不能影响原始数据
