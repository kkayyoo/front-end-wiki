# JavaScript 数据类型

## 核心分类

JS 共有 **8 种原始类型** + **引用类型（Object）**：

| 类型 | 分类 | 说明 |
|------|------|------|
| `Undefined` | 原始 | 变量已声明但未赋值 |
| `Null` | 原始 | 空值，表示"无对象" |
| `Boolean` | 原始 | `true` / `false` |
| `Number` | 原始 | 整数和浮点数，精确范围 ±2⁵³−1 |
| `String` | 原始 | 不可变字符序列 |
| `Symbol` | 原始 | ES6，唯一标识符 |
| `BigInt` | 原始 | ES2020，任意精度整数 |
| `Object` | 引用 | 包含 Array、Function、Date、RegExp 等 |

## 原始类型 vs 引用类型

```js
// 原始类型：值拷贝，互不影响
let a = 10;
let b = a;
b = 20;
console.log(a); // 10

// 引用类型：地址拷贝，修改会相互影响
let obj1 = { name: "张三" };
let obj2 = obj1;
obj2.name = "李四";
console.log(obj1.name); // 李四 ← 这是面试和实际开发中最常见的坑！
```

> **实际踩坑**：函数参数传对象/数组时，内部修改会影响外部。防御方式：用展开运算符 `{...obj}` 或 `structuredClone(obj)` 深拷贝。

## 类型判断

### typeof

```js
typeof undefined  // 'undefined'
typeof null       // 'object' ⚠️ 历史 bug，null 不是 object
typeof true       // 'boolean'
typeof 42         // 'number'
typeof 'str'      // 'string'
typeof Symbol()   // 'symbol'
typeof 42n        // 'bigint'
typeof {}         // 'object'
typeof []         // 'object' ⚠️ 无法区分数组和对象
typeof function(){} // 'function'
```

### instanceof

```js
[] instanceof Array   // true
[] instanceof Object  // true（数组也是对象）
1 instanceof Number   // false ⚠️ 原始类型不行

// 手写 instanceof
function myInstanceof(instance, Constructor) {
  let proto = Object.getPrototypeOf(instance);
  while (proto !== null) {
    if (proto === Constructor.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}
```

### 精准判断（推荐）

```js
Object.prototype.toString.call(null)      // '[object Null]'
Object.prototype.toString.call([])        // '[object Array]'
Object.prototype.toString.call({})        // '[object Object]'
Object.prototype.toString.call(new Date()) // '[object Date]'
```

## Symbol

```js
// 每次调用都是唯一的
Symbol('a') === Symbol('a') // false

// 常用场景：对象唯一 key，防止属性名冲突
const KEY = Symbol('key');
const obj = { [KEY]: 'value' };

// Symbol 不会被 for...in / Object.keys 枚举到
```

> **面试补充**：Symbol 在大型项目中用于定义"私有"属性或协议（如 `Symbol.iterator`、`Symbol.toPrimitive`）。React 内部就用 Symbol 标记 ReactElement 类型防伪造。

## BigInt

```js
// Number 的精度极限
Number.MAX_SAFE_INTEGER // 9007199254740991 (2⁵³-1)
9007199254740991 + 1 === 9007199254740992 // true
9007199254740991 + 2 === 9007199254740992 // true ⚠️ 精度丢失！

// BigInt 解决方案
9007199254740991n + 2n // 9007199254740993n ✅

// 注意：BigInt 不能直接与 Number 混算
1n + 2 // TypeError: Cannot mix BigInt and other types
Number(1n) + 2 // 3（需显式转换）
```

> **实际场景**：后端返回的 ID（如订单号、userId）超过 `2⁵³-1` 时，JSON.parse 会丢失精度。解决方案：后端返回字符串格式，或前端用 `json-bigint` 库解析。

## 面试高频题

**Q: typeof null 为什么是 'object'？**
> 历史遗留 bug（JS 首版 32 位实现中，null 的位模式与 object 相同）。ECMAScript 提案修复过，但因破坏性太大被否决，永久保留。面试答出这个背景加分。

**Q: 判断一个值是否为数组，最佳方式？**
```js
Array.isArray([])     // ✅ 推荐，ES5+，跨 iframe 可靠
[] instanceof Array   // ⚠️ 跨 iframe 失效（不同执行上下文的 Array 不同）
Object.prototype.toString.call([]) === '[object Array]' // ✅ 兼容老项目
```

**Q: == 和 === 的区别？隐式类型转换规则？**
```js
// == 会触发隐式类型转换，=== 不会
null == undefined  // true（特殊规则）
null === undefined // false
0 == false         // true（false 转 Number 为 0）
'' == false        // true
NaN == NaN         // false（NaN 不等于任何值，包括自身）
```
> **实际开发**：eslint 规则 `eqeqeq` 强制用 `===`。唯一例外：`x == null` 可同时检测 `null` 和 `undefined`。
