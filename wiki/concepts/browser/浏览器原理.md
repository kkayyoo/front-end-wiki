# 浏览器原理

## 从输入 URL 到页面显示

1. **DNS 解析**：域名 → IP 地址（使用 UDP 协议）
   - 查找顺序：浏览器 DNS 缓存 → 操作系统缓存 → 路由器缓存 → ISP DNS → 递归/迭代查询

2. **建立 TCP 连接**：三次握手（HTTPS 还需 TLS 握手）

3. **发起 HTTP 请求**：GET/POST 等请求报文发送到服务器

4. **服务器响应**：返回 HTML 等资源

5. **四次挥手**：关闭 TCP 连接

6. **浏览器渲染**：解析 HTML/CSS，构建 DOM + CSSOM → 渲染树 → 布局 → 绘制

**涉及的协议**：DNS（UDP）、TCP/IP、TLS（HTTPS）、HTTP、ARP

## 浏览器渲染流程

```
HTML → DOM Tree ──┐
                  ├→ Render Tree → Layout（布局）→ Paint（绘制）→ Composite（合成）
CSS  → CSSOM    ──┘
```

### 详细步骤

1. **解析 HTML**，构建 DOM Tree（字节 → Token → Node → DOM Tree）
2. **解析 CSS**，构建 CSSOM（Style Rules）
3. **合并**生成 Render Tree（只含可见节点，`display:none` 不在其中）
4. **Layout（布局/回流）**：计算每个节点的位置和大小
5. **Paint（绘制）**：将节点绘制成像素
6. **Composite（合成）**：GPU 合成各图层输出到屏幕

> **注意**：`<script>` 标签会阻塞 HTML 解析（JS 可能修改 DOM），`<link>` CSS 会阻塞渲染（影响 CSSOM 构建）。

## 重排（Reflow）vs 重绘（Repaint）

**重排（回流）**：元素的几何属性变化（位置、尺寸、布局），需重新计算布局。代价高。

**重绘**：元素外观变化（颜色、背景），不影响布局。代价相对低。

**规则**：重排一定触发重绘；重绘不一定触发重排。

### 触发重排的操作

```javascript
// 会触发重排
element.style.width = '100px';
element.style.display = 'none';
document.body.appendChild(newEl);
window.resize;

// 读取这些属性会强制刷新（强制同步布局）
element.offsetWidth
element.scrollTop
element.getBoundingClientRect()
```

### 避免重排的优化方案

```typescript
// ❌ 逐条修改样式，触发多次重排
el.style.width = '100px';
el.style.height = '200px';
el.style.margin = '10px';

// ✅ 方案1：批量修改样式类
el.classList.add('new-style');

// ✅ 方案2：DocumentFragment 离线操作
const fragment = document.createDocumentFragment();
items.forEach(item => fragment.appendChild(createEl(item)));
container.appendChild(fragment); // 一次性插入 DOM

// ✅ 方案3：transform 动画（不触发 Layout）
el.style.transform = 'translateX(100px)'; // GPU 加速，只触发 Composite

// ✅ 方案4：will-change 提升为合成层
el.style.willChange = 'transform'; // 提前通知浏览器创建独立图层
```

> **实际项目**：在 Azure Data Copy 的数据表格中，大量行数据更新时使用虚拟滚动（只渲染可见区域）+ DocumentFragment 批量插入，避免频繁触发重排。

## JS 垃圾回收机制（V8）

V8 使用**分代回收**策略：

### 新生代（短生命周期对象）
- 使用 **Scavenge 算法**（复制算法）
- 分为 From 和 To 两个空间
- From 中存活的对象复制到 To，然后清空 From
- 多次 GC 仍存活 → 晋升到老生代

### 老生代（长生命周期对象）
- 使用**标记清除（Mark-Sweep）**：标记不可达对象，清除释放
- **标记整理（Mark-Compact）**：清除后整理内存碎片

### 常见内存泄漏场景

```typescript
// 1. 全局变量（非严格模式下意外创建）
function leak() {
  leakedVar = 'not declared with let/const/var'; // 挂到 window 上
}

// 2. 未清理的定时器（Angular 组件销毁时未清理）
@Component({...})
export class DataComponent implements OnDestroy {
  private timer: any;

  ngOnInit() {
    this.timer = setInterval(() => this.updateData(), 1000);
  }

  ngOnDestroy() {
    clearInterval(this.timer); // ✅ 必须清理！否则内存泄漏
  }
}

// 3. 未移除的事件监听（DOM 引用 + 闭包）
// ❌ 组件销毁后监听器仍持有 DOM 引用
const el = document.getElementById('btn');
el.addEventListener('click', handler);

// ✅ 组件销毁时移除
el.removeEventListener('click', handler);

// 4. 闭包持有过大对象
function createClosure() {
  const largeData = new Array(1000000).fill('data');
  return () => largeData[0]; // 闭包持有 largeData 整个数组
}
```

## 进程 vs 线程 vs 协程

| 概念 | 说明 | 资源 |
|---|---|---|
| **进程** | 操作系统资源分配的基本单位 | 独立内存空间 |
| **线程** | CPU 调度的基本单位，进程内执行 | 共享进程内存 |
| **协程** | 用户态轻量级线程，程序自己管理调度 | 比线程更轻量 |

**浏览器的进程模型**：
- Chrome 每个 Tab 是独立的**渲染进程**（崩溃互不影响）
- 主要进程：浏览器主进程、渲染进程（每个 Tab）、GPU 进程、网络进程
- **JS 是单线程**的，但浏览器是多进程多线程的

## Cookie vs sessionStorage vs localStorage

| 对比 | Cookie | sessionStorage | localStorage |
|---|---|---|---|
| 大小 | ~4KB | ~5MB | ~5MB |
| 生命周期 | 设置过期时间 | 标签页关闭清除 | 永久 |
| 服务端 | 自动携带 | 否 | 否 |
| 跨标签 | 是 | 否 | 是 |

## 浏览器的主要组成部分

1. **用户界面**：地址栏、书签、前进/后退按钮
2. **浏览器引擎**：用户界面与渲染引擎之间的桥梁
3. **渲染引擎**：解析 HTML/CSS，显示内容（Blink/WebKit/Gecko）
4. **网络模块**：HTTP 请求处理
5. **JS 解释器**：解析执行 JS（V8/SpiderMonkey）
6. **数据存储**：Cookie/localStorage/IndexedDB

## 面试高频题

**Q: 为什么操作 DOM 慢？**

> DOM 属于渲染引擎，JS 属于 JS 引擎，两者通过"桥接"通信，有额外开销。且修改 DOM 可能触发重排/重绘，代价高昂。最小化 DOM 操作是性能优化的核心原则。

**Q: script 标签放在 `<head>` 和 `</body>` 前的区别？**

> 放在 `<head>` 中会阻塞 HTML 解析（除非加 `defer`/`async`）。放在 `</body>` 前时 DOM 已解析完成，不阻塞渲染。
> - `defer`：异步下载，DOM 解析完后执行，保持顺序
> - `async`：异步下载，下载完立即执行，不保证顺序

**Q: 什么是合成层（Composite Layer）？为什么要提升合成层？**

> 合成层由 GPU 独立处理，不影响其他图层的重绘。`transform`、`opacity` 动画在合成层中执行，不触发 Layout 和 Paint，性能极高。`will-change: transform` 可提前提升合成层。
