# 音频播放器全局状态管理

> 百度前端 Agent 面试考点（Q16）。考察为什么音频播放器需要全局状态，而不是组件局部状态。

## 为什么音频播放器必须全局状态（Q16）

### 核心问题

音频播放器有**跨页面/跨组件持久播放**的需求，局部状态无法满足：

| 问题 | 局部状态（组件内） | 全局状态 |
|------|-----------------|---------|
| 切换页面时播放中断 | ❌ 组件销毁，播放停止 | ✅ 状态持久，继续播放 |
| 多个组件控制同一播放器 | ❌ 数据不同步 | ✅ 单一数据源 |
| 进度条与播放按钮分离 | ❌ 通信困难 | ✅ 订阅同一状态 |
| 收藏/历史联动 | ❌ 需要大量 prop drilling | ✅ 直接读取全局状态 |

### 典型场景

```
用户在「歌曲列表」页点击播放
  → 切换到「歌词」页
  → 切换到「个人中心」页
  → 底部播放器始终显示当前播放状态
```

如果是局部状态：每次路由跳转组件销毁 → 播放中断。

### Angular 实现（NgRx）

```typescript
// state/player.state.ts
export interface PlayerState {
  currentTrack: Track | null;
  isPlaying: boolean;
  currentTime: number;
  duration: number;
  volume: number;
  playlist: Track[];
}

// actions
export const play = createAction('[Player] Play', props<{ track: Track }>());
export const pause = createAction('[Player] Pause');
export const setProgress = createAction('[Player] Set Progress', props<{ time: number }>());

// 任意组件都可以 dispatch
this.store.dispatch(play({ track: selectedTrack }));

// 任意组件都可以 select
this.currentTrack$ = this.store.select(selectCurrentTrack);
this.isPlaying$ = this.store.select(selectIsPlaying);
```

### React 实现（Zustand，轻量方案）

```typescript
interface PlayerStore {
  currentTrack: Track | null;
  isPlaying: boolean;
  currentTime: number;
  play: (track: Track) => void;
  pause: () => void;
  seek: (time: number) => void;
}

const usePlayerStore = create<PlayerStore>((set) => ({
  currentTrack: null,
  isPlaying: false,
  currentTime: 0,
  
  play: (track) => {
    set({ currentTrack: track, isPlaying: true });
    audioRef.current?.play();
  },
  
  pause: () => {
    set({ isPlaying: false });
    audioRef.current?.pause();
  },
  
  seek: (time) => {
    set({ currentTime: time });
    if (audioRef.current) audioRef.current.currentTime = time;
  },
}));

// 在任意组件中使用
const { currentTrack, isPlaying, play } = usePlayerStore();
```

### 全局状态的额外好处

1. **持久化**：可以用 `localStorage` 记住上次播放位置（Redux Persist / Zustand persist）
2. **开发工具**：Redux DevTools 可以时间旅行调试播放状态
3. **测试友好**：状态与 UI 解耦，可以独立单元测试播放逻辑
4. **服务端同步**：全局状态可以轻松序列化发回服务端（播放记录）

## 面试 Q&A 速查（百度原题）

**Q: 音频播放器为什么用全局状态管理？**  
A: 音频播放器需要跨页面持久存在——用户切换路由时组件销毁，局部状态随之消失，播放中断。全局状态（NgRx/Zustand）作为单一数据源，不依附于任何组件生命周期，同时解决多组件（播放按钮、进度条、歌词页）数据同步问题。
